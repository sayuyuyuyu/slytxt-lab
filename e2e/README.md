# E2E テスト

Playwright でサイトと writer の主要フローをローカルだけで確認する。
本番（Cloudflare Access の内側）には繋がない。CI の必須チェックには含めていない。

## 実行方法

```sh
pnpm install
pnpm exec playwright install chromium
pnpm test:e2e
```

初回だけ `tools/writer-cloudflare` の依存も必要（`e2e/start-writer.mjs` が
無ければ自動で `pnpm install` する）。

## 構成

- `playwright.config.mjs`（リポジトリ直下）: PC（1280px）とスマホ（390px 相当、
  iPhone 13 プリセット + Chromium）の2プロジェクトで同じシナリオを回す。
- `e2e/start-writer.mjs`: writer を wrangler dev で起動（ローカル KV は
  一時ディレクトリで、実行ごとに空）。
- `e2e/start-site.mjs`: 使い捨てコピーに埋め込み確認用の記事を足して
  ビルドし、astro preview で配信する。
- `e2e/writer.spec.mjs`: writer の主要フローを確認する。
  - 下書き作成→本文編集（見出しと Spotify URL の貼り付け）→自動保存→
    カテゴリ切替とタイトル扱い（notes ではタイトル欄と確認行を出さない）→
    プレビュー（見出し・Spotify プレイヤー）→公開パネルの表示まで
    （実際の GitHub 公開はしない）。
  - 編集画面と公開フィクスチャ記事の computed style（フォント・本文サイズ・
    行間・カラム幅、タイトルのタイポグラフィ）が一致することと、エディタ内の
    Spotify 埋め込みが実プレイヤー（iframe）で描画されること。
  - 公開済み一覧と公開完了の表示に出る X 投稿リンク。
  - タイトル欄が空の tech / journal 記事は、公開完了時の X投稿文に本文から
    補ったタイトルが入る。
  - 公開済み一覧は、タイトルが無く本文が埋め込みだけの記事を「（無題）」と
    表示する（空の下書きは従来どおり「新しい下書き」）。
  - 見出し画像の切り取り（反映・取り外し・矢印キーによる位置調整・
    大きすぎる画像の拒否）。
  - 長いタイトルの折り返しと編集列のスクロール。
  - タブを閉じている間に完了した公開結果の起動時通知。
  - 保存まわり: 端末への即時保存とサーバー同期の間引き・同一内容の再送なし、
    サーバーへ送れない場合のリロード復元、他端末と競合したときの
    サーバー優先と端末コピーの退避。
- `e2e/site.spec.mjs`: トップページのターミナル表示と、記事ページで
  Spotify 埋め込みが描画されることのスモーク確認。もう2件で、メニューが
  開閉できリンクで遷移できること（iOS のフォーカス喪失でも閉じる）と、
  メニューを Esc で閉じるとボタンへフォーカスが戻ることを確認する。
